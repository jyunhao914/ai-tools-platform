# Presentation Maker Offline

此分支用來把 Presentation Maker 改造成可完全離線執行的桌面簡報製作軟體；目前仍在開發中，尚非完整 AI 簡報產品。

## 桌面產品入口

安裝依賴後執行 `presentation-maker-offline-app`。首頁提供兩個主要入口：貼上大綱，或匯入 PPTX／DOCX／PDF／TXT；最近專案可雙擊重開。貼上大綱後先看辨識出的頁數與標題，再按「建立並匯出 PPTX…」，即可保存專案並產生可在 PowerPoint 編輯的簡報。編輯器可修改頁面標題與文字物件、預覽風格、畫區域標記、保存區域備註、加入並保存來源資料。這是有限功能的工程版，不是完整 AI 簡報產品：目前大綱流程只排版既有文字，不會呼叫文字模型擴寫、生成圖片或套用 AI 修改；區域備註及參考資料只會保存，不會觸發修改或生成。DOCX／PDF 內嵌圖片抽取、OCR、完整母片／複雜圖層保真及圖像式匯出尚未完成。

貼上大綱時，可用 `# 簡報名稱` 作為專案名稱，以 `## 投影片標題` 標示各頁；也支援以空行分頁。貼上視窗提供 macOS `⌘V`、右鍵貼上及「從剪貼簿貼上」按鈕；內容變更後會自動重新辨識，也可按「預覽大綱」。確認辨識結果後，選「建立並匯出 PPTX…」完成目前唯一完整的產出路徑。編輯器中的風格預覽只影響目前排版示意與匯出樣式，不代表生成了新內容或圖片。

## 基準模型

- 文字與流程規劃：`Qwen3.8-27B`
- 圖片生成與編修：`Qwen/Qwen-Image-2.1`
- 簡報輸出：沿用既有 PPTX 解析、內容保留、圖片佇列、失敗續作與組裝邏輯

模型權重在安裝後由使用者下載至本機模型目錄；簡報內容、圖片、提示詞與生成結果不得傳送至外部服務。

影像後端是可替換的本機 adapter，使用者可指定相容的本機 checkpoint。應用程式不呼叫雲端圖片服務、內容審查 API 或遠端安全分類器，也不新增提示詞封鎖或依內容類型中止流程；這代表「無外部審查」，不代表任何模型權重都保證生成所有內容。技術性錯誤（記憶體不足、載入失敗、推論崩潰）會保存為 `paused_technical_failure` 並可接續，不會被記錄成內容拒絕。本文不宣稱存在官方名為「無審查版」的 Qwen checkpoint。

## 執行架構

```text
桌面介面
  ├─ 專案與五種入口操作
  ├─ 一次收齊輸出、圖片策略與風格
  └─ 顯示逐頁進度與可續作狀態
          │
          ▼
本機工作流程控制器
  ├─ Qwen3.8-27B：大綱、內容映射、版面規劃、圖片提示詞
  ├─ Qwen-Image-2.1：生成、重繪、自由配圖與局部編修
  ├─ PPTX 引擎：圖像式／可編輯式組裝
  └─ SQLite 專案狀態：斷電、當機或重新啟動後續作
```

## 必須保留的流程鐵律

1. 上傳 PPTX 後先提供五種操作：保留、縮減、擴增、還原大綱、擷取風格。
2. 製作流程一次收齊輸出類型、全份圖片策略與風格，不逐題反覆詢問。
3. 圖片策略包含不用圖片、沿用原圖、超擬真重繪、自由配圖；全份採同一基準。
4. 超擬真重繪以接近原圖為目標；該頁失敗時改用自由配圖，再失敗只讓該圖片區域沿用原圖。
5. 任何單一圖片失敗不得停止其他頁面與 PPTX 組裝。
6. 重複查詢狀態不得消耗生成次數；每次實際推論都必須留下請求與結果證據。
7. 內容與頁面不得遺漏；最終必須產出可開啟的 PPTX。
8. 可編輯式簡報不限制單頁圖片數，由內容與版面決定。
9. 風格優先於沿用原圖；沿用素材時仍依選定風格完成整體排版。
10. 網路、伺服器或電腦中斷後，從已保存的專案狀態接續。

## 第一階段交付

- macOS Apple Silicon 桌面版
- 首次啟動模型下載與磁碟空間檢查
- 本機 Qwen3.8-27B 推論介面（Apple Silicon 優先使用 MLX，保留 GGUF 相容介面）

文字模型不會由程式自動下載。使用者可在進階設定選取既有的 MLX 模型資料夾或 GGUF 檔案；程式會檢查格式、必要檔案與 manifest 完整性。

2026-09-25 本機驗證發現既有 `Qwen3.8-27B-Uncensored-MLX-8bit` 權重雖通過隨附 manifest 的 SHA-256，但其執行需求記錄指向 `mlx-serve`，未驗證本程式採用的 `MLX-LM`；以當前 `mlx-lm 0.31.3` 做短生成時，多組提示皆產生亂碼。因此程式將此模型標記為「權重存在、目前後端不可用」，拒絕把它當成可用文字模型。這不是權重完整性錯誤；需要相容的推論引擎／模型並通過真實文字輸出驗收後，才能啟用 AI 大綱功能。

模型、生成快取與專案輸出使用三個分開的位置，預設建議選擇外接 SSD。程式不會把模型複製到 Hugging Face 預設快取；可用 `MODEL_HOME`／`HF_HOME` 指向選定磁碟，所有 backend 只引用該單一權重位置。下載前會估算容量並要求額外保留至少 20 GB；空間不足會阻止操作。生成快取可安全清除，不會刪除模型或專案輸出。

開發機會優先偵測既有的 LM Studio MLX 模型：`~/.cache/lm-studio/models/orcarouter/Qwen3.8-27B-Uncensored-MLX-8bit`。此目錄只原地引用，不會複製；啟動健康檢查會確認模型目錄與 safetensors 分片存在。

Qwen-Image-2.1 會自動偵測 `~/.cache/lm-studio/models/Qwen/Qwen-Image-2.1`。只有 `model_index.json`、processor、text_encoder、transformer、vae 與索引列出的每個 safetensors 分片都存在，且找不到任何 `.incomplete` 檔案時才會標記為權重完整。

2026-09-23 本機離線載入驗證通過：PyTorch 2.10.0、Diffusers 0.41.0.dev0（commit `8b3c707`）、Transformers 5.17.0、MPS 可用；`QwenImage21Pipeline.from_pretrained(..., local_files_only=True)` 成功載入全部五個元件。這驗證權重和載入流程，尚不等同完整圖片生成／編修驗收。相容套件版本記錄於 `requirements-inference-macos.txt`。
- 本機 Qwen-Image-2.1 生成／編修佇列
- 既有 PPTX 輸入、五種操作與完整圖片策略
- 圖像式及可編輯式 PPTX 輸出
- 中斷續作與逐頁結果保存
- 兩頁大綱及既有《融合8.pptx》完整流程驗收

## 硬體基線

目前開發機為 Apple M5 Pro、64 GB 統一記憶體、arm64。初版以單機單使用者與一次一個圖片推論工作為基準，避免文字模型和圖片模型同時常駐造成記憶體壓力。
